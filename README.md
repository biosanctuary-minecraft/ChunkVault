# ChunkVault

Fabric-мод для Minecraft **26.2** (протокол 776, требует Java 25), который во время игры
сохраняет прогруженные клиентом чанки и содержимое открытых контейнеров (сундуки, бочки,
шалкеры) в отдельный мир в формате ванильного save-файла — по сути мини-версия
World Downloader под текущую версию игры.

## Как это работает

Мод НЕ лезет в сеть сам и не парсит протокол напрямую — он подключается к тем же точкам,
где ванильный клиент уже обработал пакет сервера, и просто копирует данные, которые
клиент и так получил и держит в памяти:

1. **Чанки** — мод слушает момент, когда `ClientPacketListener` обрабатывает
   `ClientboundLevelChunkWithLightPacket` и `LevelChunk` уже создан в `ClientLevel`.
   После этого чанк сериализуется в NBT вручную (см. `ChunkNbtWriter`) и пишется в
   `.mca`-регион через `RegionFile`, как это делает ванильный сервер.
2. **Контейнеры** — мод запоминает координаты блока, по которому кликнули ПКМ
   (`BlockInteractionMixin`), а когда открывается `ChestMenu`/`GenericContainerMenu`,
   содержимое инвентаря копируется прямо в клиентский `BlockEntity` этого блока.
   Дальше при сохранении чанка эти предметы уходят в `.mca` вместе со всем остальным —
   ровно так это делает оригинальный WDL.
3. **level.dat** — генерируется отдельно (`LevelDatWriter`), т.к. клиент не хранит
   полный level.dat сервера. Внутри — минимально необходимые поля, чтобы ванильный
   клиент согласился открыть папку как мир в одиночной игре.

Всё пишется в `.minecraft/chunkvault/<имя-мира>/` — обычная структура сохранения
(`region/`, `level.dat`, `data/`), которую можно открыть как обычный singleplayer-мир.

## Важно понимать про эту версию кода

Я собирал это **без доступа к реальным jar-файлам Minecraft 26.2 и без возможности
скомпилировать проект локально** (в моём окружении нет сети). Логика и структура —
рабочие и основаны на том, как устроены такие моды годами, но конкретные имена классов/
методов Mojang-маппинга **могут разойтись** с тем, что реально в 26.2 (это новая версия,
маппинги и Fabric API под неё ещё свежие). Это нормально для первой сборки —
`./gradlew genSources` в GitHub Actions скачает реальные маппинги, и компилятор укажет
ровно те места, где имя отличается. В таких случаях правьте по **смыслу метода**
(что он делает), а не по названию — я оставил комментарии `// CHECK:` в местах,
где уверенность ниже 100%.

## Функционал

- [x] Сохранение прогруженных чанков в валидный `.mca`
- [x] Захват содержимого открытых контейнеров
- [x] Генерация рабочего `level.dat`
- [x] Команды `/chunkvault start <имя>`, `/chunkvault stop`, `/chunkvault status`
- [ ] Сущности (мобы/предметы на земле) — не реализовано в этой версии
- [ ] GUI-настройки (радиус, авто-старт) — пока только команды

## Сборка через GitHub Actions

Просто запушьте репозиторий — воркфлоу `.github/workflows/build.yml` сам:
1. ставит JDK 25 (Temurin);
2. кэширует Gradle/Loom;
3. собирает мод (`./gradlew build`);
4. кладёт готовый `.jar` из `build/libs/` в артефакты сборки (вкладка Actions → ваш run → Artifacts).

Если сборка упадёт на этапе компиляции — это почти наверняка несовпадение имени метода/класса
с актуальным маппингом. Откройте лог, найдите `cannot find symbol`, и в соответствующем
файле поправьте имя (см. раздел выше).

## Использование

```
/chunkvault start survival_backup   # начать запись, папка сохранения — survival_backup
... ходите по миру, открывайте сундуки ...
/chunkvault stop                    # дописать регионы и level.dat
```

Готовый мир появится в `.minecraft/chunkvault/survival_backup/` — скопируйте его в
`.minecraft/saves/`, чтобы открыть в одиночной игре.

## Легальность и этика

Мод сохраняет только то, что клиент **легитимно получил** от сервера в ходе обычной игры
(прогруженные чанки, открытые вами сундуки) — он не выкачивает непрогруженные/незагруженные
данные и не является читом (x-ray, эспи и т.п.). Тем не менее:

- на многих серверах офлайн-копирование мира запрещено правилами — проверьте это
  до использования;
- сохранённое содержимое чужих сундуков — это фактически слепок чужого прогресса;
  используйте с уважением к другим игрокам;
- используйте только на серверах, где у вас есть на это разрешение.
